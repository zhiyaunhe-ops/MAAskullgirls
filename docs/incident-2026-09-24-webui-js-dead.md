## 1. 现象

| 观测面 | 原记录 |
|---|---|

| 后端 | 手工API请求200；服务端无对应语法告警 |
| 前端 | Invalid or unexpected token |

## 2. 根因

~~~text
Python普通三引号内的JS源码：
  confirm('提示\n\n说明')
Python求值：
  \n → 真实换行
浏览器收到：
  JS单引号字符串含真实换行 → SyntaxError
~~~

| 原记录错误 | 校正 |
|---|---|
| “引入提交e33b427” | 函数／错误转义由b6fcec8引入；以diff为据 |
| “源码本身含三个裸换行” | 源码含单层反斜杠转义；Python求值后成为裸换行 |
| “换行只在注释里” | diff中字符串确有单层换行转义 |
| “服务端正常⇒必然前端” | 仅缩小范围；需浏览器错误／输出脚本证明 |

## 3. 为什么波及全站，而不是只坏「关机」键

| 条件 | 后果 |
|---|---|
| 同一经典script块存在语法错误 | 该块不执行；事件注册／轮询未启动 |
| HTML／CSS独立解析 | 布局仍可正常显示 |
| 其它script块 | 不由此自动推断失效 |

## 4. 为什么长时间没被发现

| 检查 | 能否发现此错误 |
|---|---|
| Python ast.parse | 否；Python字符串合法 |
| HTTP 200／手工API | 否；不验证浏览器脚本 |
| 导出后的JS语法检查 | 能检出 |
| 浏览器console／交互 | 可观测前端执行／功能结果 |
| 旧GET /api/settings日志 | 非根因证据；“地址栏补全触发”缺独立证据 |

## 5. 定位过程

| 顺序 | 操作／证据 |
