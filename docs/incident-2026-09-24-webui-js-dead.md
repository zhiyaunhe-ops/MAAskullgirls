# 事故复盘：WebUI 全站按钮失效（2026-09-24）

**修复提交**：`dec4acc`　**引入提交**：`e33b427`（feat(webui): 达标关模拟器 + MuMu/游戏启停按钮 + 6 套主题）
**作者（引入方）**：hy4 模型　**定位与修复**：Cairn

---

## 1. 现象

用户在浏览器打开 `http://127.0.0.1:8790`，页面**正常渲染**（布局、样式、主题全对），
但**所有按钮点了毫无反应**——包括「开始」「暂停」「启动 MuMu」「启动游戏」「关机」、
场次管理、每日任务池、主题切换，无一例外。

服务端侧完全正常：`/api/state`、`/api/sessions`、`/api/daily`、`/api/jjc` 手工 curl 全部 200，
进程健康、日志无 err。

## 2. 根因

`tools/pf_webui.py` 第 855 行，`onMumuOffClick()` 里的一句 `confirm`：

```javascript
if (!confirm('关闭 MuMu 模拟器？\n\n关闭后 bot 无法运行（会先自动暂停）。\n需要时点「开始」会自动重新拉起模拟器。')) return;
```

`\n` **只写在源码注释 / 提交说明里，没落到字符串上**——字符串字面量内部是三个真实换行符。
`_HTML` 是普通 `"""` 三引号（非 raw），Python 把裸换行**原样**输出进 `<script>`，
浏览器解析到第 110 行即：

```
Uncaught SyntaxError: Invalid or unexpected token
```

## 3. 为什么波及全站，而不是只坏「关机」键

这是本次最容易误判的点。

浏览器对 `<script>` 块是**原子解析**的：**语法错误在块内第一行代码执行之前就抛出**，
整个块一条语句都不执行。所以从错误点（L110）往下的

- 所有 `addEventListener(...)` —— 按钮事件一条都没注册上
- `setInterval(pollState, 1500)` / `pollMumu(4000)` —— 状态轮询没起来
- `applyTheme(...)` / 初始化调用 —— 全没跑

而 HTML 与 CSS 是独立解析的，照常渲染。于是表现为「**界面在，点哪都不动**」。

> 换句话说：**这不是 N 个 bug，是 1 个 bug 造成的 N 个症状。**
> 若按「哪个按钮坏修哪个」的思路排查，会白跑很久。

## 4. 为什么长时间没被发现

**服务端零告警。** 这个模块把 JS 塞进 Python 三引号字符串，两边换行语义不一致，
而失败发生在**浏览器端**：

| 观测面 | 表现 |
|---|---|
| HTTP 状态 | 200（HTML 本身就是合法 UTF-8 文本） |
| 服务端日志 | 干净，无 err |
| 后端 API | 手工 curl 全通 |
| 浏览器 console | ⚠️ 唯一的错误信号 |

日志里唯一沾边的两条其实是误导项：

```
[09:24:20][warn] 未知请求 GET /api/settings <- 127.0.0.1
[09:24:26][warn] 设置已更新: 能量门槛=4, 喜爱筛选=True ...
```

`/api/settings` 只支持 POST，那个 GET 是浏览器地址栏自动补全触发的——
**是「前端已死」的下游后果，不是原因**。

## 5. 定位过程

服务端一切正常 ⇒ 必然在前端 ⇒ 不能只看服务端。

```bash
# ① 抽页面里的内联 script，合成一个文件
curl -s http://127.0.0.1:8790/ -o ui.html
# ② 语法校验（这是决定性的一步）
node --check app.js
#   → D:\Downloads\app.js:110
#     if (!confirm('关闭 MuMu 模拟器？
#                  ^^^^^^^^^^^^^
#     SyntaxError: Invalid or unexpected token
# ③ 定位到源码行
grep -n "关闭 MuMu 模拟器" tools/pf_webui.py
```

再扫一遍「奇数个单引号的行」确认**全页仅此一处**，排除其它未闭合字符串。

## 6. 修复

```diff
-  if (!confirm('关闭 MuMu 模拟器？\n\n关闭后……')) return;
+  if (!confirm('关闭 MuMu 模拟器？\\n\\n关闭后……')) return;
```

`\n` 写成 `\\n`，Python 侧产出 `\n` 两个字符，浏览器拿到的是**转义序列**而非裸换行。

### 验证链

1. `ast.parse` 通过（Python 语法没问题——**注意这一步修前也是通过的**）
2. 从 `_HTML` 导出页面 → `node --check` **全部内联脚本通过**（修前报 L110 SyntaxError）
3. 全页奇数单引号行扫描 = 0
4. 重启服务后浏览器实测按钮恢复

## 7. 教训与护栏

### 7.1 这类 bug 的固有特征：**静默**

Python 语法检查、服务端路由测试、API 冒烟**全部无法发现它**。
唯一的探针是浏览器，或等价的 JS 静态检查。
⇒ **改 `_HTML` 里的 JS，提交前必须跑一次 `node --check`。**

### 7.2 给后续 AI 的硬约束

hy4 模型在 `e33b427` 里同时做了三件事（达标关模拟器 + MuMu 启停按钮 + 6 套主题），
引入这个 bug 时**没有任何一层护栏拦得住**。原因不是它不小心，而是：

> **`_HTML` 这种「Python 里嵌 JS」的写法，把两边最容易出错的语义（换行转义）缝在了一起，
> 却没有对应的检查。**

建议（择机实施，非本次范围）：

- **【低成本 · 优先】** 在仓库加一个 pre-commit hook 或 `tools/lint_html_js.py`：
  导出 `_HTML` → 抽 `<script>` → `node --check`。把「改 JS 要过 node --check」
  从**人的纪律**变成**机器的门禁**。
- **【根治】** `_HTML` 里所有含换行的 JS 字符串统一改用反引号模板字面量
  （JS 里模板字面量允许真实换行，语义天然正确），或把内联 JS 拆成独立 `.js` 静态文件
  （`/static/` 已支持，`chart.umd.min.js` 就是这么放的）。
- 顺带：`_HTML` 可考虑改 raw 三引号 `r"""`——**但不能只做这一半**，
  因为那会让本来正确的 `\n` 也变成字面量。必须与 7.2 第二条一起做。

### 7.3 排查心法

**「界面能打开但按钮全死」⇒ 优先怀疑页面 JS 整体没执行，而不是逐个按钮排查。**

第一步不是读业务代码，而是把页面脚本抽出来做语法校验。

## 附：本次为何能快速定位

用户给的线索质量高——「**点界面的按钮都没反应**」比「关机按钮不好使」信息量大得多：
前者直接指向**全局性**故障，排除了「某个 handler 逻辑写错」这一大类可能，
把搜索空间压缩到「脚本有没有跑起来」这一个问题上。

同时，用户此前那句「2026-09-22 早上被误点过一次」的注释，恰好说明
`onMumuOffClick()` 是**较晚加的代码**——新增代码即高风险区，
对照 `git log -p` 很容易锁定引入提交。
