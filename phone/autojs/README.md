# AutoJs6 悬浮窗结算挂机 — 从零配置教程

目标形态：游戏里悬浮一个小控制条（开始/停止/场数统计，可拖动），点「开始」就自动循环
`VICTORY/DEFEAT 判场 → REMATCH 再战 / CONTINUE 略过奖励`。全程免 Root、免无障碍服务、
免录屏弹窗——点击和截屏都走 Shizuku（shell 权限），悬浮窗只是普通 UI 权限。

```
AutoJs6 (悬浮控制条 + 识别循环, JS)
   │ shizuku("screencap -p ...")   ← 截屏, 免录屏弹窗
   │ shizuku("input tap x y")      ← 点击, 免无障碍
   ▼
Shizuku 服务 (shell uid, 由系统「无线调试」激活)
   ▼
Android Framework → SGM 游戏
```

> 与 `phone/` Termux 方案的关系：两套并存互不影响。这套的优势是悬浮窗 + 可打包成独立
> APK；Termux 那套的优势是 MaaTouch 毫秒级触控。结算循环用这套足够。

---

## 0. 前置检查（一次性，全部在系统设置里）

| # | 设置项 | 路径 | 为什么 |
|---|---|---|---|
| 1 | **USB 调试** | 设置 → 更多设置 → 开发者选项 | Shizuku 激活的基础 |
| 2 | **USB 调试（安全设置）** | 同上（需插 SIM 卡 + 登录小米账号，首次开启有 10 秒倒计时） | ⚠️ **不开则 `input tap` 注入被系统吞掉**——表现为日志显示点了但屏幕无反应 |
| 3 | **无线调试** | 同上 | Shizuku 的启动入口，每次重启手机后要重新打开 |

HyperOS 装第三方 APK 被拦时，按你平时装 pfwidget 的方式放行即可。

## 1. 安装并启动 Shizuku（权限源头）

1. 手机浏览器打开 `https://github.com/RikkaApps/Shizuku/releases`，下载最新的
   `shizuku-xx.apk` 并安装（国内打不开 GitHub 就走加速前缀，如
   `https://ghproxy.net/https://github.com/...`）。
2. 打开 Shizuku → 首页「开发者选项中已启用无线调试？」点进去按引导开启。
3. 启动服务（免 Root 方式）：
   - Shizuku 首页点 **「通过无线调试启动」**；
   - 系统跳到「无线调试」面板 → 点 **「使用配对码配对设备」**，会显示一组 **6 位配对码** 和 **配对端口**；
   - 回到 Shizuku，通知栏弹出的输入框里输入 **配对码**，等它自动完成配对；
   - 配对成功后 Shizuku 自动启动，首页状态变为绿色 **「运行中」**。
4. （HyperOS）Shizuku 应用详情 → 省电策略 → **无限制**；最近任务里下拉锁定。

> ⚠️ 手机**每次重启后**：无线调试 + Shizuku 服务都要重新激活（进 Shizuku 再点一次
> 「通过无线调试启动」即可，配对只需第一次）。

---

## 2. 安装 AutoJs6（脚本引擎 + 悬浮窗）

1. 打开 `https://github.com/SuperMonster003/AutoJs6/releases`，下载最新的
   `autoJs6-vx.x.x.apk` 安装（同上可加加速前缀）。
2. 首次启动按提示授予：**存储权限**（读脚本和模板）、**悬浮窗权限**
   （设置里叫「显示在应用上层」）。漏了也没关系，第 4 步运行时会再引导。
3. **连接 Shizuku**：AutoJs6 主界面左侧边缘往右滑出抽屉 → 找到 **Shizuku 权限开关 → 打开**。
   （官方要求三件：Shizuku ≥11 已安装、Shizuku 服务已启动、AutoJs6 抽屉开关已开）
4. 验证连接：AutoJs6 首页点底部终端图标，输入：
   ```js
   shizuku("echo ok")
   ```
   输出 `ok` 即通。报红就回到第 1 步检查 Shizuku 状态和抽屉开关。

## 3. 把脚本和模板放进手机

电脑上 `phone/autojs/` 目录整体拷到手机，最终结构（以放在 `/sdcard/脚本/sgm_settle/` 为例）：

```
/sdcard/脚本/sgm_settle/
├── settle_bot.js        # 悬浮窗挂机脚本
└── templates/
    ├── victory.png      # VICTORY! 大字
    ├── defeat.png       # DEFEAT! 大字
    ├── btn_rematch.png  # 橙色 REMATCH 按钮
    ├── btn_continue.png # 紫蓝 CONTINUE 按钮
    └── btn_quit.png     # 紫色 QUIT 按钮
```

传输方式任选：USB 数据线（MTP）、微信文件传输助手、Tailscale + 局域网。`templates/`
五个 PNG 不要改名——脚本按文件名加载。

## 4. 运行

1. 打开 AutoJs6 → 文件列表进入 `sgm_settle/` → 点 **`settle_bot.js`** 运行。
   （若提示无存储/悬浮窗权限，按弹窗引导授予后重跑）
2. 屏幕上出现黑色小悬浮条：`[开始] [停止] 00:00 0场 0胜0负`，按住空白处可拖动
   （**运行中也能拖**）；松手时距屏幕左/右边缘 70px 内会自动**缩进只留一小条**，
   按住露出的部分拖出即恢复。
3. 手机切到 SGM，停在任意界面（大厅/结算页都行）。
4. 点悬浮条 **「开始」**。正常的话状态栏实时显示 `时长 场数 胜负`，AutoJs6 日志页
   （侧栏 → 日志）开始出现：
   ```
   [场] VICTORY (共 1 胜 0 负)
   [动] 先手 (CONTINUE) → (1234,1024)
   [动] CONTINUE 略过 → (820,1024)
   [动] REMATCH (第 2 场) → (820,1024)
   ```
5. 停止：点悬浮条「停止」，toast 给出总统计（时长/场数/胜负/CONTINUE 次数）。
   关掉悬浮窗：AutoJs6 侧栏 → 停止全部脚本（悬浮窗随脚本停止自动消失）。

**识别节奏（两阶段状态机，既快又省）**：

- 战斗阶段：只查 VICTORY!/DEFEAT! 两个大字（800ms 一轮，战斗本身几十秒）；
- 命中大字 → 计场，并**直接先手点右槽固定位置**——胜局该格是 CONTINUE（略过结算），
  败局该格恰好是 REMATCH（直接再战），两种情况都不用做按钮匹配；
- 结算/奖励阶段：只在按钮三槽查 REMATCH/CONTINUE（350ms 一轮，快速跟点），
  连续 3 帧无按钮 = 已进入下一场战斗，自动回到大字监测。

## 5. 调参（识别不对时再看）

都在 `settle_bot.js` 顶部配置区，改完保存重跑：

| 症状 | 调整 |
|---|---|
| 日志一直 `[!!] 30s 无识别` 但游戏明明在结算页 | `MIN_SIM` 从 0.72 降到 0.65 再试；仍不行 = 分辨率/主题差异大，需重裁模板（见下） |
| 日志显示点击了，**屏幕没反应** | 不是脚本问题——「USB 调试(安全设置)」没开，回第 0 步 |
| 该点 REMATCH 时点了 CONTINUE | `MIN_SIM` 调高 0.05，拉开按钮间区分度 |
| 先手点击点错格（少见：结算页按钮布局变化） | 删掉 loop 里「先手」段（`FIRST_TAP` 相关 4 行），退回纯模板匹配流程 |
| 结算反应慢 / 漂移错过 | `RESULT_MS` 从 350 降到 250；`TAP_DELAY_MS`（点后过场等待）按游戏动画加减 |
| 战斗阶段太耗电 | `BATTLE_MS` 从 800 调到 1500（战斗几十秒，检测不用勤） |

重裁模板：游戏换版本/换分辨率后按钮样式变了，在电脑上截一张新的结算图，把坐标填进
`phone/assets/settle/make_templates.py` 的 `CROPS`，跑一遍后把新 PNG 拷进 `templates/`。

## 6. 打包成独立 APK（可选，想要"真 App"时）

AutoJs6 内置打包：文件列表长按 `sgm_settle` 文件夹（或脚本）→ 菜单 → **打包 APK**。
注意：

- 打包界面里勾选/保留 **悬浮窗** 与 **存储** 权限声明；
- Shizuku 授权是运行时的，打出来的 APK 首次启动仍需手机上装着 Shizuku 且服务在运行；
- 图标/应用名在打包界面自定义，产物自签安装（HyperOS 装包照旧放行）。

打出来的包本质上 = 这个脚本 + AutoJs6 运行时，升级脚本只需重新打包。

## 7. 故障排查

| 症状 | 原因 → 处理 |
|---|---|
| `shizuku("echo ok")` 报错/无输出 | Shizuku 服务没启动（重启后失效）→ Shizuku App 重新「通过无线调试启动」；或 AutoJs6 抽屉里 Shizuku 开关没开 |
| 点「开始」提示 Shizuku 未连接 | 同上；另外确认手机没开「禁止 Shizuku 后台启动」类限制 |
| 悬浮条出现又立刻消失 | AutoJs6 后台被杀 → 省电策略无限制 + 最近任务锁定；通知栏 Acquire wakelock |
| 日志狂刷 `[!!] 无识别` | 游戏不在结算页属正常；一直刷 = 模板对不上 → 第 5 步调参/重裁 |
| 点了 REMATCH 但没进下一场 | 偶发：延迟不足。`TAP_DELAY_MS` 加到 1800；或该局弹出的是别的对话框（人工看一眼） |
| 手机重启后不工作 | 三件事：无线调试重开、Shizuku 重新启动、AutoJs6 重新运行脚本 |

## 8. 已知边界

- 识别走 `images.findImage`（AutoJs6 内置 OpenCV），与 PC 侧 `phone/settle_bot.py` 同源
  模板/阈值，但分数口径略有差异——以你手机实测微调 `MIN_SIM` 为准。
- 断线重连、维护弹窗等非常规页面：当前只告警不处理（`STALL_SEC` 触发），遇到多了就把
  截图加进 `make_templates.py` 扩一个模板（Python 侧标定后两边共用）。
- 息屏后 screencap 截到黑屏、input 仍生效但游戏可能暂停——挂机请保持亮屏
  （游戏内设置或系统息屏时长调长）。
