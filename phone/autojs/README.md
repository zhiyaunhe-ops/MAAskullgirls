# AutoJs6 悬浮窗结算挂机 — 从零配置教程

目标形态：游戏里悬浮一个小控制条（开始/停止/场数统计，可拖动），点「开始」就自动循环
`VICTORY/DEFEAT 判场 → REMATCH 再战 / CONTINUE 略过奖励`。全程免 Root、免无障碍服务、
免录屏弹窗——点击和截屏都走 Shizuku（shell 权限），悬浮窗只是普通 UI 权限。

```
AutoJs6 (悬浮控制条 + 识别循环, JS)
   │ shizuku("screencap -p ...")   ← 截屏, 免录屏弹窗
   │ shizuku("input tap x y")      ← 点击, 免无障碍
   ▼
Shizuku 服务 (shell uid, 由系统「无线调试」激活)
   ▼
Android Framework → SGM 游戏
```

> 与 `phone/` Termux 方案的关系：两套并存互不影响。这套的优势是悬浮窗 + 可打包成独立
> APK；Termux 那套的优势是 MaaTouch 毫秒级触控。结算循环用这套足够。

## 0. 前置检查（一次性，全部在系统设置里）

| # | 设置项 | 路径 | 为什么 |
|---|---|---|---|
| 1 | **USB 调试** | 设置 → 更多设置 → 开发者选项 | Shizuku 激活的基础 |
| 2 | **USB 调试（安全设置）** | 同上（需插 SIM 卡 + 登录小米账号，首次开启有 10 秒倒计时） | ⚠️ **不开则 `input tap` 注入被系统吞掉**——表现为日志显示点了但屏幕无反应 |
| 3 | **无线调试** | 同上 | Shizuku 的启动入口，每次重启手机后要重新打开 |

HyperOS 装第三方 APK 被拦时，按你平时装 pfwidget 的方式放行即可。

## 1. 安装并启动 Shizuku（权限源头）

1. 手机浏览器打开 `https://github.com/RikkaApps/Shizuku/releases`，下载最新的
   `shizuku-xx.apk` 并安装（国内打不开 GitHub 就走加速前缀，如
   `https://ghproxy.net/https://github.com/...`）。
2. 打开 Shizuku → 首页「开发者选项中已启用无线调试？」点进去按引导开启。
3. 启动服务（免 Root 方式）：
   - Shizuku 首页点 **「通过无线调试启动」**；
   - 系统跳到「无线调试」面板 → 点 **「使用配对码配对设备」**，会显示一组 **6 位配对码** 和 **配对端口**；
   - 回到 Shizuku，通知栏弹出的输入框里输入 **配对码**，等它自动完成配对；
   - 配对成功后 Shizuku 自动启动，首页状态变为绿色 **「运行中」**。
4. （HyperOS）Shizuku 应用详情 → 省电策略 → **无限制**；最近任务里下拉锁定。

> ⚠️ 手机**每次重启后**：无线调试 + Shizuku 服务都要重新激活（进 Shizuku 再点一次
> 「通过无线调试启动」即可，配对只需第一次）。

## 2. 安装 AutoJs6（脚本引擎 + 悬浮窗）

1. 打开 `https://github.com/SuperMonster003/AutoJs6/releases`，下载最新的
   `autoJs6-vx.x.x.apk` 安装（同上可加加速前缀）。
2. 首次启动按提示授予：**存储权限**（读脚本和模板）、**悬浮窗权限**
   （设置里叫「显示在应用上层」）。漏了也没关系，第 4 步运行时会再引导。
3. **连接 Shizuku**：AutoJs6 主界面左侧边缘往右滑出抽屉 → 找到 **Shizuku 权限开关 → 打开**。
   （官方要求三件：Shizuku ≥11 已安装、Shizuku 服务已启动、AutoJs6 抽屉开关已开）
4. 验证连接：AutoJs6 首页点底部终端图标，输入：
   ```js
   shizuku("echo ok")
   ```
   输出 `ok` 即通。报红就回到第 1 步检查 Shizuku 状态和抽屉开关。

## 4. 运行

1. 打开 AutoJs6 → 文件列表进入 `sgm_settle/` → 点 **`settle_bot.js`** 运行。
   （若提示无存储/悬浮窗权限，按弹窗引导授予后重跑）
2. 屏幕上出现黑色小悬浮条：`[开始] [导航] [停止] [结束] [◀] 00:00 …`，按住空白处可拖动；点「◀」折成贴边小箭头（点箭头展开；箭头可拖动，松手自动贴回近侧边缘，转屏后 5s 内重新贴边）
   （**运行中也能拖**）；面板松手自动拉回屏内，隐藏/展开用「◀」小箭头完成。
3. 手机切到 SGM，停在任意界面（大厅/结算页都行）。
4. 点悬浮条 **「开始」** = 直接开结算循环（游戏已在战斗中/结算页时用这个）；
   点 **「导航」** = 自动从启动游戏一路走到开打再接结算循环（见下一节）。正常的话
   状态栏实时显示 `时长·小状态(战斗监测/结算页/导航中/自愈中) 今日场数 本次场数·每分钟场次 胜负`，AutoJs6 日志页（侧栏 → 日志）开始出现：
   ```
   [场] VICTORY (共 1 胜 0 负)
   [动] 先手 (CONTINUE) → (1234,1024)
   [动] CONTINUE 略过 → (820,1024)
   [动] REMATCH (第 2 场) → (820,1024)
   ```
5. 停止：点悬浮条「停止」，toast 给出总统计（时长/场数/胜负/CONTINUE 次数）。
   关掉悬浮窗：AutoJs6 侧栏 → 停止全部脚本（悬浮窗随脚本停止自动消失）。

**识别节奏（两阶段状态机，既快又省）**：

- 战斗阶段：只查 VICTORY!/DEFEAT! 两个大字（800ms 一轮，战斗本身几十秒）；
- 命中大字 → 计场，并**直接先手点右槽固定位置**——胜局该格是 CONTINUE（略过结算），
  败局该格恰好是 REMATCH（直接再战），两种情况都不用做按钮匹配；
- 结算/奖励阶段：只在按钮三槽查 REMATCH/CONTINUE（350ms 一轮，快速跟点），
  连续 3 帧无按钮 = 已进入下一场战斗，自动回到大字监测。

### 4.1 今日场次与每日上限（pf_store）

- 每判到一局结算（VICTORY/DEFEAT）记一场，累计到 `/sdcard/sgm_settle/store.json`，
  **每场落盘**：脚本重启、崩溃都不丢今日计数；跨过 0 点（本机日历天）自动归零。
- 悬浮条统计里显示 `今日N场`（设了上限则是 `今日N/上限`），停止时的 toast 也带今日总数。
- 每日上限在 `settle_bot.js` 顶部 `DAILY_CAP`（默认 `0` = 不限）：判完当前这局达到上限
  就**自动停止**，不再点任何按钮、人留在结算页（安全，不消耗资源）；已达上限时点
  「开始 / 导航」也会被拦下并提示，改 `DAILY_CAP` 或次日即可继续。
- 这是 PC 版 pf_store 场次系统的手机简化版：只做今日计数 + 上限，子场次/规则按钮组仍在 PC 侧。

## 5. 导航挂机（启动→大厅→EVENTS→Pillow Talk→自动开打）

点 **「导航」** 交给 `pf_nav.js` 执行，全链路：

```
启动游戏 → 等大厅(促销弹窗X/通用弹窗X/结算残局逃逸/偶发点房子) → 点 EVENTS 菱形
  → 轮播翻卡划到目标活动卡 Pillow Talk (ev_target 模板命中居中卡才点;
    目标卡 PLAY! 置灰 = 报错不跳过, 绝不点 SKIP!)
  → 点 PLAY! → FIGHT_STEPS 王关链: 地图右移×2(右边界钳位)
    → 最右绿✓颜色锚点定位王关(大小/平移不敏感) → 点 FIGHT!
  → 战斗开场 AUTO(脑子)+3x 速度自检 (同 pf_bot 逻辑)
  → 无缝接结算循环 (VICTORY/DEFEAT → CONTINUE→REMATCH; stall 时先试关弹窗)
```

模板来源口径：`hall_events/ev_play/ev_target` 裁自 K70 真机帧（1280×576 基准）；
`scene_x/modal_x` 由 PC MuMu 模板 ×0.8 双轴转换（2026-10-04 多尺度实测 0.98 分，
PC→手机 UI 尺寸比 = 576/720）。

### 5.1 首次使用：采集 → 标定（当前状态）

导航的界面识别模板还没从真机裁出来（结算循环那 5 个已有）。**缺模板时点「导航」
会自动转采集模式**，不用记命令：

1. 点悬浮条「导航」→ 日志提示转采集，往 `/sdcard/sgm_settle/nav/` 每 2.5s 存一帧（共 60 帧 ≈ 2.5 分钟）；
2. 采集期间**手动**把流程走一遍：大厅 → EVENTS → 划到 Pillow Talk 卡 → PLAY! →
   选最右战斗节点 → 点 PLAY → 战斗开场（脑子/速度泡露出即可停）；
3. 采集完电脑 `adb pull /sdcard/sgm_settle/nav/`（或 Tailscale），按
   `phone/assets/settle/make_templates.py` 同款思路裁出 `hall_events.png`、`ev_play.png`、
   `ev_target.png`（Pillow Talk 卡标题字样，避开相邻卡边缘；以及可选 `scene_x` /
   `vs_fight` / `battle_spd_1x|2x|3x`），放进手机 `templates/`；
4. 按 5.2 填 `pf_nav.js` 的坐标/步骤配置 → 重跑 `node test_nav.js` → 再点「导航」。

### 5.2 待标定清单（都在 pf_nav.js 顶部配置区，坐标基准 1280×576）

| 项 | 用途 | 现状 |
|---|---|---|

| `scene_x.png` / `modal_x.png` | 促销弹窗 X / 通用弹窗方 X (waitHall+轮播每帧关弹窗; settle stall 逃生) | ✅ PC 模板 ×0.8 转换 |
| `FIGHT_STEPS` | 王关链: 地图右移×2 → 绿✓锚点 → FIGHT! | ✅ 真机走链标定, 重放逐像素可重复 |
| `HOME_XY` / `CARD_ROI` / `SWIPE_FROM/TO` | 回家按钮 / 居中卡区域 / 翻卡手势 | ✅ K70 真机实测 |
| `BRAIN_BOX`/`BRAIN_XY`/`SPD_ROI`/`SPD_XY` | 战斗开场脑子+速度泡 | ✅ 真机战斗帧实测 (HUD 屏幕居中锚定)；速度模板 1x/3x 判档 (0.95), 仅导航/自愈开场判一次 — 速度只在程序重启后重置 |

安全规则：模板/坐标没标定的界面一律不盲点——宁可停在安全点等人，防误触
SKIP!/购买等消耗资源的入口。`FIGHT_STEPS` 标定示例见 `pf_nav.js` 配置区注释。

### 5.3 AUTO/3x 自检说明

与 MuMu 侧 pf_bot 完全同逻辑：点 FIGHT 后等 1.8s（开场介绍画面人物不动，唯一安全
点击窗口）→ 脑子图标亮度判自动战斗（V 均值 ≥75=亮）→ 速度泡三模板判当前倍率，
非 3x 点一下升一档并复验。两项设置游戏内**跨场持久**，所以只在导航后第一场做一次；
识别不到就告警跳过，不影响挂机。

### 5.4 能量换人（pf_select.js：逻辑已备，待真机接入）

PF bot 最核心的调度（PC 版的灵魂）：卡底黄钉数 = 能量，≥4 可出战，每场耗 1，
固定队伍连刷数场必撞「能量不足」弹窗。`pf_select.js` 已把 PC 侧逻辑按同参数搬成
纯函数（Node 测试覆盖，不碰 AutoJs6 全局，像素读取 px(x,y) 由接入层注入）：

- **黄钉识别**：`isBolt` / `countBolts` / `readSlots` / `readRoster` — 严格黄掩码
  R≥240 G≥200 B≤105 + 列占比游程计数，与 `tools/pf_vision.py` 同参，金卡淡黄底免疫；
- **编队修正状态机**：`planFixTeam` — 规则槽优先 → 候选区从左往右换首个达标 →
  无达标翻页（上限 30）→ 拖拽复验失败则偏移逐档递进并归零候选列重试（fix_team 同语义）；
- **规则色判定**：`ruleLit` — FIGHT 按钮高饱和占比 ≥15% 判规则满足。

未接入的唯一原因：编队页几何（`GEOM`，槽位/候选钉条行带与拖拽落点）是 PC MuMu
1280×720 实测坐标，手机侧未标定——按安全规则不盲点。接入路径：跑一次 5.1 采集时
手动把编队页也走一遍，裁出钉条行带坐标填 `GEOM`，再在导航链 FIGHT_STEPS 后接
「读槽位 → planFixTeam → 拖拽」循环；规则芯片（元素/类别）筛选留了 refillRule 钩子后补。

## 6. 调参（识别不对时再看）

都在 `settle_bot.js` 顶部配置区，改完保存重跑：

| 症状 | 调整 |
|---|---|
| 日志一直 `[!!] 30s 无识别` 但游戏明明在结算页 | `MIN_SIM` 从 0.72 降到 0.65 再试；仍不行 = 分辨率/主题差异大，需重裁模板（见下） |
| 日志显示点击了，**屏幕没反应** | 不是脚本问题——「USB 调试(安全设置)」没开，回第 0 步 |
| 该点 REMATCH 时点了 CONTINUE | `MIN_SIM` 调高 0.05，拉开按钮间区分度 |
| 先手点击点错格（少见：结算页按钮布局变化） | 删掉 loop 里「先手」段（`FIRST_TAP` 相关 4 行），退回纯模板匹配流程 |
| 结算反应慢 / 漂移错过 | `RESULT_MS` 从 350 降到 250；`TAP_DELAY_MS`（点后过场等待）按游戏动画加减 |
| 战斗阶段太耗电 | `BATTLE_MS` 从 800 调到 1500（战斗几十秒，检测不用勤） |

重裁模板：游戏换版本/换分辨率后按钮样式变了，在电脑上截一张新的结算图，把坐标填进
`phone/assets/settle/make_templates.py` 的 `CROPS`，跑一遍后把新 PNG 拷进 `templates/`。

## 7. 打包成独立 APK（可选，想要"真 App"时）

AutoJs6 内置打包：文件列表长按 `sgm_settle` 文件夹（或脚本）→ 菜单 → **打包 APK**。
注意：

- 打包界面里勾选/保留 **悬浮窗** 与 **存储** 权限声明；
- Shizuku 授权是运行时的，打出来的 APK 首次启动仍需手机上装着 Shizuku 且服务在运行；
- 图标/应用名在打包界面自定义，产物自签安装（HyperOS 装包照旧放行）。

打出来的包本质上 = 这个脚本 + AutoJs6 运行时，升级脚本只需重新打包。

## 8. 故障排查

| 症状 | 原因 → 处理 |
|---|---|
| `shizuku("echo ok")` 报错/无输出 | Shizuku 服务没启动（重启后失效）→ Shizuku App 重新「通过无线调试启动」；或 AutoJs6 抽屉里 Shizuku 开关没开 |
| 点「开始」提示 Shizuku 未连接 | 同上；另外确认手机没开「禁止 Shizuku 后台启动」类限制 |
| 悬浮条出现又立刻消失 | AutoJs6 后台被杀 → 省电策略无限制 + 最近任务锁定；通知栏 Acquire wakelock |
| 日志狂刷 `[!!] 无识别` | 游戏不在结算页属正常；一直刷 = 模板对不上 → 第 5 步调参/重裁 |
| 点了 REMATCH 但没进下一场 | 偶发：延迟不足。`TAP_DELAY_MS` 加到 1800；或该局弹出的是别的对话框（人工看一眼） |
| 手机重启后不工作 | 三件事：无线调试重开、Shizuku 重新启动、AutoJs6 重新运行脚本 |
| 点「导航」转采集/提示缺模板 | 正常——导航模板还没标定（见 5.1）；走完采集→裁模板→填坐标即可 |
| 悬浮条不显示「今日N场」/计数不累计 | 缺 pf_store.js（要与 settle_bot.js 同目录）；或 /sdcard/sgm_settle/ 不可写 |
| 导航日志停在「FIGHT_STEPS 未标定」 | PLAY! 之后没标定坐标，脚本按安全规则不盲点；按 5.2 填 FIGHT_STEPS（划轨/最右节点/PLAY） |
| 一直翻卡最后报「没划到目标卡」 | ev_target 模板与卡面对不上（换活动/裁图带了相邻卡边缘）→ 重裁居中卡标题区域 |
| 报「目标卡 PLAY! 置灰」 | Pillow Talk 本身没次数/能量了 → 不是脚本问题 |
